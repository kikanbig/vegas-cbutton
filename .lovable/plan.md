
## Цель

Расширить CButton фиксацией **Этапа 2 «Консультация клиента»** со строгой привязкой к конкретному клиенту (нажатию 4-секторной кнопки). База данных должна поддерживать всю воронку (включая будущий Этап 3 «Закрытие сделки»), UI/админка пока показывают этапы 1–2 и анкету отказов.

---

## 1. База данных (миграция)

### Новая таблица `client_consultations`
Фиксирует Этап 2. Одна запись = одна консультация по клиенту.

Поля (без стандартных):
- `button_press_id` — ссылка на `button_presses.id` (UNIQUE, ON DELETE CASCADE) — привязка к клиенту с Этапа 1
- `user_id` — продавец (для RLS и аналитики)
- `consultation_type` — enum `consultation_type`: `express` | `deep`
- `outcome` — enum `consultation_outcome`:
  - `proposal_sent` — Сформировано КП (цена/условия/сроки)
  - `project_offered` — Предложен проект / назначена встреча (только для `deep`)
  - `refused` — Отказ клиента от предложения
- `refusal_reason` — enum `refusal_reason` (NULLABLE, обязателен только при `outcome='refused'`):
  - `price` — Не соответствует цена
  - `product` — Не нравится товар
  - `other` — Без указания причин
- `recorded_at` — фактическое время фиксации

Валидация триггером:
- `outcome='project_offered'` допустимо только если `consultation_type='deep'`
- `refusal_reason` обязателен при `outcome='refused'`, иначе NULL

### Новая таблица `client_deals` (под будущий Этап 3, без UI)
- `button_press_id` (UNIQUE FK)
- `user_id`
- `closed_at`
- Только структура, без UI; админка покажет «0 закрытий», пока пусто.

### RLS и GRANT
- `authenticated`: SELECT/INSERT/UPDATE своих записей (по `user_id = auth.uid()`)
- `service_role`: ALL
- Админы (`has_role(auth.uid(),'admin')`) видят все строки

### Агрегации для админки
Новая SQL-функция `admin_get_funnel_stats()` возвращает JSON:
- Всего клиентов (Этап 1)
- Из них с консультацией (Этап 2)
- Разбивка по `consultation_type`
- Разбивка по `outcome`
- Разбивка по `refusal_reason`
- Конверсия Этап1 → Этап2 → КП → Сделка (когда появятся deals)
- Та же разбивка по продавцам

## 2. UI приложения продавца (`/app`)

**Логика после нажатия 4-секторной кнопки:**

1. Кнопка фиксирует клиента (как сейчас) → запись `button_presses` создаётся.
2. Сразу открывается **полноэкранный модальный экран «Консультация»**, привязанный к id этой записи. Экран можно отложить (кнопка «Позже» → попадает в локальный список «Ожидают фиксации»).
3. Экран состоит из шагов:
   - **Шаг 1.** Тип консультации: две большие кнопки «Экспресс-консультация» / «Глубинная проработка».
   - **Шаг 2.** Итог. Для экспресс — 2 кнопки (Сформировано КП / Отказ). Для глубинной — 3 кнопки (Проект-встреча / КП / Отказ).
   - **Шаг 3** (только если Отказ). Причина: Цена / Товар / Без указания.
4. После сохранения — короткий toast «Консультация записана», экран закрывается, возвращаемся к 4-секторной кнопке.

**Список ожидающих фиксации (внизу или в шторке):**
- Клиенты текущей смены без `client_consultations` записи.
- Тап → открывает тот же модальный экран.
- Поддержка офлайн-очереди (как существующий механизм `offlineSync` для нажатий).

## 3. Админка

Новая секция **«Воронка продаж»** на `/admin`:

- Карточки KPI: Клиенты → Консультации → КП → Закрытия (с % конверсии между этапами).
- Pie/Bar чарт «Тип консультации» (Экспресс vs Глубинная).
- Bar чарт «Итог консультации» (Проект / КП / Отказ).
- Bar чарт «Причины отказа».
- Таблица по продавцам: клиенты, консультации, КП, отказы, % перехода Клиент→КП.

Экспорт Excel (`admin-export`) — добавить листы:
- «Консультации» — детализация (продавец, клиент, тип, итог, причина, время).
- «Воронка по продавцам» — сводка.

## 4. Технические детали

- Edge function `admin-funnel-stats` (рекурсивная пагинация, аналогично `admin-stats`).
- `admin-stats` дополнить пробросом данных воронки в общий ответ (или отдельный хук `useFunnelStats`).
- Хук `useClientConsultations` для клиентского приложения (создание/чтение «ожидающих»).
- Real-time подписка в админке на `client_consultations`.
- `verify_jwt = false` для нового edge function + проверка claims внутри.

## 5. Что НЕ делаем сейчас
- UI Этапа 3 «Закрытие сделки» — таблица создана, но кнопок и записей нет.
- Поля суммы/номера заказа — не вводим, закрытие сделки идёт через учётную систему.
- Изменение текущей 4-секторной кнопки — она остаётся как точка входа в воронку.
